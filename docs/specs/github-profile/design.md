# Design: GitHub Profile README

## Context

GitHub profile `github.com/CongChu99` currently shows a default user page with no README. The developer is a Python Tech Lead + DevSecOps engineer + Odoo specialist + AI tools builder with a niche expertise combination that is invisible on a plain profile.

The goal is to transform the profile into a branded, animated, self-updating portfolio using entirely free OSS tooling — zero cost, ~1 day build, then runs automatically via GitHub Actions cron.

**Key constraints from research:**
- GitHub does not execute JavaScript — no dynamic behavior in-browser
- GitHub partially supports HTML (`<img>`, `<div>`, `<table>` allowed; complex CSS stripped)
- GitHub caches external SVGs aggressively (5–60 min) — snake animation must be committed locally
- Repository must be named exactly `CongChu99/CongChu99`

---

## Architecture Overview

```
[Profile Page: github.com/CongChu99]
        |
        └─ README.md (GFM + inline HTML)
                |
                ├─ External SVG services (capsule-render, readme-typing-svg, shields.io)
                │   └─ Requested fresh on each page load by visitor's browser
                │
                ├─ Vercel-hosted stats APIs (github-readme-stats, streak-stats, trophies)
                │   └─ Dynamic SVG computed on request from GitHub API
                │
                └─ Locally committed SVG (snake animation)
                    └─ Generated by GitHub Actions daily → committed to `output` branch
                        └─ Referenced from README with raw GitHub URL or relative path

[GitHub Actions: .github/workflows/snake.yml]
        └─ Cron: daily at 12:00 UTC
                └─ Platane/snk@v3
                        └─ Reads contribution graph
                        └─ Writes SVG to output/github-contribution-grid-snake-dark.svg
                        └─ Commits to `output` branch
```

**Two rendering paths:**
1. **On-demand** (visitor loads profile): Browser fetches external SVG URLs from Vercel services — live data, cached by GitHub's CDN
2. **Scheduled** (GitHub Actions): Snake SVG regenerated daily and committed to repo — served from GitHub's own CDN, no external dependency at view time

## Components

### Component 1: Header / Footer (capsule-render)
- **Purpose**: Provides animated wave SVG banner for visual framing of the profile
- **Interface**: `GET https://capsule-render.vercel.app/api?type=waving&color=714B67,017E84&height=200&section=header&text=CongChu99&fontSize=50&fontColor=fff`
- **Dependencies**: capsule-render Vercel deployment (external)
- **Fallback**: Alt text displayed if service is unavailable

### Component 2: Typing Tagline (readme-typing-svg)
- **Purpose**: Animated SVG cycling through identity statements for immediate persona communication
- **Interface**: `GET https://readme-typing-svg.demolab.com?font=Fira+Code&size=22&pause=1000&color=017E84&width=600&lines=Python+Tech+Lead...`
- **Dependencies**: readme-typing-svg Vercel deployment (external)
- **Lines configured**:
  ```
  Python Tech Lead 🐍
  DevSecOps Engineer 🔐
  Odoo Developer %26 ERP Architect 🏗️
  AI Tools Builder 🤖
  Building business automation on Odoo %26 Linux
  ```

### Component 3: Bio Section
- **Purpose**: Static markdown text establishing identity for both technical and non-technical visitors
- **Interface**: Plain GFM paragraph — no external dependencies
- **Dependencies**: None
- **Content**: 3–5 sentences covering specializations and professional context

### Component 4: Tech Stack Badges
- **Purpose**: Visual, scannable representation of the full skill set organized by domain
- **Interface**: `<img>` tags with shields.io badge URLs + devicon SVG icons
- **Dependencies**: shields.io CDN (external), devicon CDN (external)
- **Layout**: 4 `<div align="center">` blocks, one per domain group, with badge images inline
- **4 Groups**: AI/ML & Tools | Odoo & ERP | DevSecOps | Languages & Tools

### Component 5: GitHub Stats Cards
- **Purpose**: Live GitHub activity metrics proving active contribution
- **Interface**:
  - Stats: `GET https://github-readme-stats.vercel.app/api?username=CongChu99&theme=tokyonight&show_icons=true`
  - Streak: `GET https://streak-stats.demolab.com?user=CongChu99&theme=tokyonight`
  - Top Langs: `GET https://github-readme-stats.vercel.app/api/top-langs?username=CongChu99&layout=compact&theme=tokyonight`
- **Dependencies**: github-readme-stats public Vercel (self-host recommended), streak-stats service
- **Layout**: Stats + Streak side-by-side in `<div align="center">`, Top Langs centered below

### Component 6: Snake Animation (GitHub Actions)
- **Purpose**: Animated contribution graph snake; doubles as DevOps competency signal (CI/CD in profile repo)
- **Interface**: Local SVG committed to `output` branch, referenced as raw GitHub URL
  - `https://raw.githubusercontent.com/CongChu99/CongChu99/output/github-contribution-grid-snake-dark.svg`
- **Dependencies**: Platane/snk@v3 GitHub Action (runs in GitHub Actions runtime)
- **Trigger**: Daily cron `0 12 * * *` via `.github/workflows/snake.yml`

### Component 7: GitHub Trophies
- **Purpose**: Achievement display row for social proof of GitHub activity
- **Interface**: `GET https://github-profile-trophy.vercel.app/?username=CongChu99&theme=tokyonight&row=1&column=6&no-frame=true`
- **Dependencies**: github-profile-trophy Vercel deployment (external)

### Component 8: Social / Contact Links
- **Purpose**: Navigation to professional profiles and contact methods
- **Interface**: `<a>` tags wrapping shields.io badge images
- **Dependencies**: shields.io CDN
- **Required links**: LinkedIn, contact email (at minimum)

## Data Model

This project has no database. The "data model" is the URL parameter schema for each widget:

**capsule-render parameters:**
```
type=waving | color=<hex1>,<hex2> | height=200 | section=header|footer
text=<name> | fontSize=50 | fontColor=fff | animation=twinkling
```

**readme-typing-svg parameters:**
```
font=Fira+Code | size=22 | pause=1000 | color=<hex>
width=600 | lines=<line1>;<line2>;...
```

**github-readme-stats parameters:**
```
username=CongChu99 | theme=tokyonight | show_icons=true
bg_color=0D1117 | title_color=714B67 | text_color=C9D1D9 | icon_color=017E84
hide_border=true
```

**shields.io badge URL structure:**
```
https://img.shields.io/badge/<label>-<color>?style=for-the-badge&logo=<logo>&logoColor=white
```

**snake.yml workflow schema:**
```yaml
name: Generate Snake Animation
on:
  schedule:
    - cron: "0 12 * * *"
  workflow_dispatch:
permissions:
  contents: write
jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: Platane/snk@v3
        with:
          github_user_name: CongChu99
          outputs: |
            dist/github-contribution-grid-snake.svg
            dist/github-contribution-grid-snake-dark.svg?palette=github-dark
      - uses: crazy-max/ghaction-github-pages@v3
        with:
          target_branch: output
          build_dir: dist
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Error Handling

| Error Condition | Behavior | Mitigation |
|---|---|---|
| External SVG service down (capsule-render, stats, etc.) | GitHub shows broken image placeholder with alt text | Write descriptive `alt` text on all `<img>` tags; accept occasional outage for non-critical widgets |
| Snake workflow `403 Permission denied` | Workflow fails; no SVG committed | Ensure `permissions: contents: write` in `snake.yml`; verify repo Actions settings allow workflow write access |
| Stats card rate limited (public Vercel instance) | Card shows "Couldn't generate stats" error SVG | Self-host github-readme-stats as Phase 2 improvement |
| GitHub image cache stale | Snake animation appears to not update for up to 1 hour | Reference committed local SVG (not external URL) — GitHub serves committed files more reliably |
| Workflow breaks silently over time | Profile shows stale/broken snake SVG | GitHub Actions default email notification on workflow failure; monitor Actions tab periodically |

## Goals / Non-Goals

**Goals:**
- Transform profile into an animated, brand-consistent portfolio in ~1 day
- Visually communicate 4 specializations within 10 seconds of loading
- Demonstrate DevOps competency through GitHub Actions automation in the profile itself
- Apply Odoo brand colors (`#714B67`, `#017E84`) consistently across all widgets
- Work reliably in both GitHub light and dark mode

**Non-Goals:**
- Custom SVG/CSS animation crafting (high effort, not proportional to impact)
- Spotify Now Playing integration (personal signal, OAuth maintenance overhead not justified)
- Mobile-layout optimization (GitHub mobile app renders Markdown acceptably)
- Multi-language support or localized profile
- Blog post automation (no confirmed blog source)

## Decisions

### Decision 1: Hybrid approach (Approaches 2 + 3) over static-only
**Chosen**: Third-party Vercel-hosted widgets (no Actions needed) for hero elements + GitHub Actions only for snake animation.
**Rationale**: Static widgets (header, stats, badges) work immediately with zero setup. Snake animation requires Actions but proves DevOps competency visually. Adding WakaTime or blog actions would increase maintenance surface without proportional brand benefit for MVP.
**Alternative considered**: Pure static markdown (Approach 1) — rejected because no animation and no live stats.
**Alternative considered**: Full lowlighter/metrics (Approach full Actions) — rejected because requires significant YAML configuration; overkill for MVP.

### Decision 2: Use public Vercel instances for MVP (not self-hosted)
**Chosen**: Public instances of github-readme-stats, streak-stats, trophies, capsule-render.
**Rationale**: MVP speed — self-hosting is a 15-minute improvement that can be done as Phase 2 after the profile is live and working. A rate-limited card is better than no card during initial build.
**Alternative considered**: Self-host all services immediately — rejected as over-engineering for MVP.
**Mitigation**: Document self-hosting as the first recommended post-MVP improvement.

### Decision 3: Odoo brand colors (`#714B67`, `#017E84`) as primary palette
**Chosen**: Odoo's primary brand colors applied to all widget theme parameters.
**Rationale**: Niche Odoo positioning is the strongest differentiator. Visual consistency with Odoo brand reinforces the niche identity. No other developer profile uses this color combination — instant differentiation.
**Alternative considered**: GitHub default dark green palette — rejected because it's generic and doesn't reinforce brand identity.

### Decision 4: Snake SVG committed to `output` branch (not external URL)
**Chosen**: Platane/snk commits generated SVG to `output` branch; README references raw GitHub URL.
**Rationale**: GitHub caches external SVGs for 5–60 min but serves committed repository files more reliably. Self-hosting the generated asset eliminates dependency on external service uptime at view time.
**Alternative considered**: Reference snk hosted service URL directly — rejected because caching makes it appear stale.

## Risks / Trade-offs

### Risk 1 — Third-Party Service Downtime (from research)
- **Likelihood**: Medium
- **Impact**: Broken image placeholders on profile during outage
- **Accepted trade-off**: For MVP, accept this risk. Mitigate for stats card (most visible) by self-hosting in Phase 2.

### Risk 2 — GitHub Image Caching (from research)
- **Likelihood**: High (expected GitHub behavior)
- **Impact**: Snake animation appears stale for up to 1 hour after update
- **Mitigation**: Commit SVG locally (see Decision 4) — mitigates the main cache problem.

### Risk 3 — OAuth Token Expiry (from research)
- **Likelihood**: Not applicable for MVP (no OAuth integrations in scope)
- **Future risk**: WakaTime integration (Phase 2) will require WAKATIME_API_KEY; document rotation procedure when added.

### Risk 4 — README Complexity Creep (from research Contrarian View)
- **Likelihood**: Medium
- **Impact**: Cluttered, slow-loading profile that confuses visitors
- **Mitigation**: Hard limit — MVP contains exactly the 10 components defined in spec. No additions until profile is live and feedback is gathered (Recommendation 5 from research).

### Risk 5 — GitHub Platform Policy Changes (from research)
- **Likelihood**: Low–Medium
- **Impact**: Animations or HTML breaks on future GitHub policy change
- **Mitigation**: Use standard `![alt](url)` Markdown image syntax where possible; avoid proprietary GitHub-only features.
